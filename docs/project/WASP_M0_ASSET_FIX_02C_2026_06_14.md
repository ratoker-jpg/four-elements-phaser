## 1. Root Cause (from DIAG-02B)

Wasp cyan m0 `wasp_cyan_m0_dir*.png` files were pixel-identical to the legacy `wasp_cyan_m0_hull_dir*.png` siblings (all 16 directions, MD5 match). They were hull-only crops on 512×512 canvases, not `fixed_512_frame` modular composites. The previous fix (ASSET-FIX-02A, PR #281) incorrectly replaced the original m0_dir files with the `_hull_dir` siblings, believing they matched the healthy modular family. They did not.

m0 was a structural outlier vs the healthy m1/m2/m3 family:
- Bbox 397×233 vs healthy 274×161 (1.45× larger)
- Opaque pixels ~63,859 vs healthy ~30,537 (2.09× more)
- Center shifted UP by ~47 px (nCy=0.496 vs 0.588)
- Anchor model self-centered (nCx always 0.5) instead of world-origin anchored (direction-dependent nCx)

## 2. Regeneration Source/Pipeline

### 2.1 Blender Pipeline Unavailability

Blender 3.x+ and the source .3ds model files (`Wasp_0123.3ds` + m0 textures) are not available on the CI/server environment. The modular export pipeline (`tools/blender/render_tank_sprite.py`) requires Blender and runs on the developer's local Windows machine (paths referenced in manifest: `D:\Desktop\Модели\...`).

### 2.2 Geometric Transformation Approach

Since the Blender pipeline could not be run directly, the m0_dir files were regenerated by implementing the **exact same fixed_512_frame projection transformation** that the Blender pipeline applies, derived mathematically from the m1 reference pair.

**Key geometric fact:** All wasp hull tiers (m0/m1/m2/m3) use the same 3D model geometry (`Wasp_0123.3ds`) with different textures. The `_hull_dir` files across all tiers have byte-identical alpha bounding box metrics (same bbox W×H, same centroids, same pixel counts), confirming identical projection geometry. Therefore, the transformation from `_hull_dir` → `_dir` is the same for all tiers.

**Method:**

For each of 16 directions, the affine transformation that maps m1_hull content to the m1_dir frame was computed:

1. **Scale factor** `s = avg(bbox_dir_W / bbox_hull_W, bbox_dir_H / bbox_hull_H)`
   - Derived from the m1_hull/m1_dir pair: s ≈ 0.689 (uniform across all directions)
   - This corresponds to `ortho_hull / ortho_dir` where `ortho_dir = 860`

2. **Translation** derived from alpha centroids:
   - `offset_x = centroid_dir_x - centroid_hull_x × s`
   - `offset_y = centroid_dir_y - centroid_hull_y × s`

3. **Inverse mapping** (for bilinear sampling):
   - `src_x = (out_x - centroid_dir_x) / s + centroid_hull_x`
   - `src_y = (out_y - centroid_dir_y) / s + centroid_hull_y`

This is mathematically equivalent to re-rendering through the Blender pipeline because:
- The isometric projection (azimuth=45°, elevation=35.264°, verticalStretch=3.158) is a linear (affine) mapping from 3D to 2D
- Both `_hull` and `_dir` renders use identical projection parameters, differing only in ortho scale and anchor point
- The affine relationship between the two renders is fully captured by scale + translation

**Verification on m1 reference:** Before applying to m0, the transformation was verified by transforming m1_hull and comparing against the actual m1_dir:
- Alpha IoU > 0.989 for all 16 directions
- Pixel count match within 0.3%
- Mean RGB difference 3.6–10.7 (from bilinear resampling vs native render)

## 8. Risks

1. **Bilinear resampling artifacts**: The regenerated files use bilinear interpolation of the hull-only render rather than native Blender rasterization. This may introduce very minor edge quality differences (mean RGB diff 3.6–10.7 on m1 verification). At normal game zoom, these are imperceptible.

2. **Future Blender re-export**: When the developer next runs the Blender modular export pipeline locally for Wasp cyan m0, it should produce files that are very close (but not pixel-identical) to these regenerated files. The Blender output should be committed as the authoritative version when available.

3. **No structural regression risk**: The framing, anchor, and scale now match the healthy modular family exactly. The only risk is pixel-level quality, which is bounded by the m1 verification results.
